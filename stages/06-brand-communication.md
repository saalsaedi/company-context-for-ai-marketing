# Stage 06 — Brand and communication

Domain: brand_communication  
Dependencies: 01 foundation; 05 customer scope.

## Inputs
Existing brand guide, approved copy, founder voice preferences, supported product/customer evidence.

## Review
Extract positioning, promise, tone, vocabulary, language needs, visual preferences where relevant, and banned/unsubstantiated claims.

## Investigate
Ask for examples of wording that feels right or wrong. Review proof for differentiation claims; request definition if a framework label is ambiguous.

Candidate questions (select only unanswered, useful questions):
- How should customers feel when reading your communication?
- Which phrases sound like you, and which do not?
- Which promise can you support today?

## Synthesize
Create brand taste, voice principles, approved/proposed value propositions, example messages and story candidates grounded in records.

## Validate
Brand language must not create new evidence. Superlatives, quantified outcomes and testimonials need sources. Do not invent customer stories.

## Approve
Present a compact voice sample and positioning statement for review; keep story options as proposals until accepted.

## Maturity adaptation
Idea: provisional voice and story hypotheses. MVP: early promise tied to present capabilities. Operating: existing consistency, audience variants and proof standards.

## Outputs
Brand/voice records; message examples; claim boundaries; optional founder/problem/customer/future story drafts.

Save records under domain=brand_communication; preserve record IDs in all rendered views. Use [stage summary](../templates/stage-summary.md) and update the canonical progress state after meaningful changes.

## Exit gate
Voice and core positioning are reviewable; claims have proof or qualifying language. Optional story categories are design aids, not an assumed external framework.

If blocked, log a gap type, affected claim/task, owner and next action. Continue independent draft work when possible. Review approval never changes evidence kind. See [stage engine](../references/adaptive-stage-engine.md) for transitions and [validation protocol](../references/validation-protocol.md) for release criteria.
