# Stage 03 — Products and services

Domain: products_services  
Dependencies: 01 foundation.

## Inputs
Product brief, release notes, demo, service catalog, roadmap, delivery commitments.

## Review
List each offer, intended job, availability, included functionality, limits, integrations and service boundaries.

## Investigate
Inspect current materials or a demo if available. Ask the owner to distinguish generally available, pilot, prototype and planned capabilities.

Candidate questions (choose one useful unanswered question; these are alternatives, not a questionnaire):
- What can a customer actually use or buy today?
- What would a customer receive?
- What would fall outside the offer?
- Which capabilities are planned but should never be promised yet?

## Synthesize
Create scoped current-offer records and separate roadmap aspirations/decisions. Capture onboarding, prerequisites, delivery expectations, and support boundaries.

## Validate
Do not turn a mockup into a shipped feature or an integration idea into a working connection. Qualify capacity, SLA and reliability claims.

## Approve
Present the product truth set and current limitations, with roadmap items visibly separate.

## Maturity adaptation
Idea: proposed solution and assumptions. MVP: tested versus untested functions. Launched: actual onboarding and known constraints. Operating: editions, lifecycle, support and ownership.

## Outputs
Product/service inventory; capability records; roadmap boundary; agent promise constraints.

Save records under domain=products_services; preserve record IDs in all rendered views. Use [stage summary](../templates/stage-summary.md) and update the canonical progress state after meaningful changes.

## Exit gate
An agent can describe the offer without promising unbuilt capabilities or unapproved service commitments.

If blocked, log a gap type, affected claim/task, owner and next action. Continue independent draft work when possible. Review approval never changes evidence kind. See [stage engine](../references/adaptive-stage-engine.md) for transitions and [validation protocol](../references/validation-protocol.md) for release criteria.
