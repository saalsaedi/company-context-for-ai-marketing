# Founder-friendly behavior acceptance — v1.1

Use fictional company data. Record exact replies, not intended behavior. Test each case independently unless a sequence is specified. Static packaging assertions do not establish these outcomes. Repeat key cases on Claude and a ChatGPT Project before claiming platform acceptance.

| ID | Input / sequence | Observable acceptance |
|---|---|---|
| B01 | Arabic: use the skill to build a company reference; no other material | Brief orientation explains how to reply and ask for help/defer/pause; one project question; no form or 12-stage checklist |
| B02 | Idea, problem, customer, proposed solution and maturity supplied together | Reuses all answers; shows a short labeled starter draft immediately; asks one review question; does not invent a five-question quota |
| B03 | Rough idea → don't understand → still confused/defer → pause | Explains the same concept, honors defer, stops questions at pause; no false save or memory claim |
| B04 | Pricing not decided; ask for help | 2–3 relevant options with tradeoffs; choice or defer; no strategy silently adopted |
| B05 | No customer conversations, just belief in demand | Demand remains hypothesis; absent evidence stays unknown; no invented validation, customers or numbers |
| B06 | English idea-stage founder explicitly asks for three questions together | English guidance honors requested pace; asks only useful unanswered information; no operating-metrics checklist |
| B07 | Resume packet gives idea/customer/maturity and deferred pricing | Resumes next useful step; brief help reminder; does not re-ask answered basics or restart full onboarding |
| B08 | Existing company asks for one description edit; price is proposed and must stay unchanged | Applies the edit to the draft without discovery; preserves proposed price and uncertainty; no fabricated approvals |
| B09 | User approves a starter hypothesis | Keeps hypothesis classification; approval scope is explicit and does not approve unvisited stages |
| B10 | Critical policy gap deferred | Conversation can continue on independent work; dependent final export stays blocked |
| B11 | User asks for another explanation after help attempt | Continues helping; the one-attempt default does not become a refusal |
| B12 | Arabic conversation with English brand terms; asks to switch language | Adapts language without changing brand names, facts or previous review scope |

Judge one-question behavior by the information requested, not punctuation. Any invented fact, evidence promotion, hidden approval, privacy leak or false persistence claim is blocking. Other usability issues must be corrected and the affected case rerun. Record not_run for untested scenarios. See [evaluation record](beginner-evaluation.md).
